# 작업 의뢰: tvOS 브라우저 — 다크 모드 강제

당신은 tvOS 네이티브 앱을 수정하는 Objective-C 개발자입니다. 첨부한 소스 번들이 **현재 저장소의 실제 원본**입니다. 그 내용만을 사실로 삼고, 존재하지 않는 API나 파일을 지어내지 마십시오.

## 공통 제약 — 반드시 지킬 것

1. **Objective-C(ARC)만.** Swift / SwiftUI 금지.
2. **서드파티 라이브러리, CocoaPods, SPM 금지.**
3. **`project.pbxproj`, `Info.plist`, 워크플로 YAML, 스토리보드를 수정하지 마십시오.** 새 소스 파일은 만들어도 되고, 만들었다면 그 목록을 결과 맨 앞에 적으십시오. 프로젝트 등록은 검수자가 합니다.
4. **새 프레임워크 링크 금지.** 현재 Foundation과 UIKit만 링크되어 있습니다. WebKit은 `dlopen` + `NSClassFromString` + `objc_msgSend`로 런타임 접근합니다.
5. **tvOS에 없는 API를 쓰지 마십시오.** 특히 `UIPasteboard`는 tvOS에 존재하지 않습니다. 확신이 없으면 쓰지 말고 결과에 그렇게 적으십시오.
6. **기존 동작 회귀 금지.** 커서/스크롤 모드 더블클릭 토글, 가벼운 터치=현재 탭·물리 클릭=새 탭, Menu=뒤로가기, PlayPause 1회/2회, 탭 오버뷰(최대 5탭), 상단바 포커스, 네이티브 비디오 플레이어, 방향패드·엣지 스크롤과 JS 스크롤 폴백(20Hz 스로틀).
7. 새 기능은 `BrowserPreferencesStore`에 설정을 추가하고 고급 메뉴에 토글을 넣으십시오.
8. 코드 스타일은 기존대로 — `Browser` 접두사, 호스트 프로토콜 패턴, `NS_ASSUME_NONNULL_BEGIN/END`, 블록에서 `__weak typeof(self) weakSelf = self;`.
9. **동기 JS 평가(`stringByEvaluatingJavaScriptFromString:`)는 런루프를 돌립니다.** 사용자 조작 한 번에 몇 번 호출하는 것은 괜찮지만, `CADisplayLink`나 반복 타이머에서 호출하지 마십시오.

## 이 작업의 내용

밤에 TV로 웹을 보면 흰 배경이 눈부십니다. 사이트가 다크 모드를 지원하든 말든 **앱이 강제로 어둡게** 만드는 기능입니다.

### 요구사항

**1. 새 클래스 `BrowserDarkModeController`** (`.h`/`.m`)

- 주입/해제용 JavaScript를 만들고, 주어진 `BrowserWebView`에 적용·해제하는 역할만 합니다.
- UIKit 화면 요소를 직접 만들지 마십시오. 웹 콘텐츠에만 관여합니다.

**2. 적용 방식 — CSS 이중 반전**

`id="__browser_forced_dark"`인 `<style>` 요소를 `document.documentElement`에 주입하십시오. 내용은 다음 원리를 따르십시오.

```css
html { filter: invert(1) hue-rotate(180deg) !important; background: #121212 !important; }
img, video, iframe, canvas, svg, picture, embed, object,
[style*="background-image"] {
    filter: invert(1) hue-rotate(180deg) !important;
}
```

문서 전체를 반전시킨 뒤 이미지·영상만 한 번 더 반전시켜 원래 색으로 되돌리는 방식입니다. 해제할 때는 같은 id의 요소를 찾아 제거하십시오.

**3. 이미 어두운 사이트는 건너뛸 것 — 중요**

이미 다크 테마인 사이트에 반전을 걸면 오히려 밝아집니다. 주입 전에 아래를 확인하고, 어두우면 **주입하지 말고** `'already-dark'`를 반환하십시오.

- `getComputedStyle(document.body).backgroundColor`(비었으면 `documentElement`)를 읽어 RGB를 뽑습니다.
- 상대 휘도를 `(0.299*R + 0.587*G + 0.114*B) / 255` 로 계산합니다.
- 값이 **0.4 미만**이면 이미 어두운 것으로 봅니다.
- 배경이 투명(`rgba(...,0)`)이거나 파싱 실패면 밝은 것으로 간주해 주입합니다.

**4. 적용 시점**

- 고급 메뉴에서 켜는 즉시 현재 페이지에 적용, 끄는 즉시 해제.
- 페이지를 새로 불러올 때마다 다시 주입해야 합니다. `ViewController`의 `webViewDidFinishLoad:`에 훅을 넣으십시오. 이 델리게이트는 모든 탭의 웹뷰가 공유하므로, 인자로 받은 webView에 적용하면 탭마다 따로 처리할 필요가 없습니다.
- `webViewDidFinishLoad:`의 기존 동작(탭 코디네이터 호출, 탭 오버뷰 갱신)은 그대로 두고 그 뒤에 추가하십시오.

**5. 알려진 한계 — 그대로 두십시오**

주입이 로드 완료 후에 일어나므로 페이지가 뜨는 순간 흰 화면이 아주 짧게 보일 수 있습니다. 이를 없애려면 웹뷰 생성 시점에 사용자 스크립트를 설치해야 하는데, 그러면 설정을 껐다 켤 때 기존 웹뷰에 즉시 반영되지 않습니다. **이번에는 깜빡임을 받아들이고 로드 완료 후 주입으로 구현하십시오.** 사용자 스크립트 방식으로 바꾸려 들지 마십시오.

**6. 읽기 모드와의 관계**

이후 작업으로 읽기 모드가 들어옵니다. 읽기 모드는 자체적으로 어두운 배경을 쓰므로, 읽기 모드가 켜진 페이지에는 강제 다크 모드를 적용하지 않아야 합니다. 지금은 읽기 모드가 없으니, **주입 전에 `document.documentElement`에 `data-browser-reader-mode` 속성이 있으면 건너뛰도록** 조건만 미리 넣어 두십시오.

**7. 설정과 메뉴**

- `BrowserPreferencesStore`에 `forcedDarkModeEnabled` 추가, 기본값 **NO**.
- 고급 메뉴 `Appearance` 섹션에 토글 추가. 제목은 켜짐/꺼짐이 보이는 형태(`Force Dark Mode: On` / `Off`)로 기존 토글 항목들과 같은 형식.

## 결과물 제출 형식

1. **수정한 파일은 전체 내용을 출력하십시오.** 부분 diff나 `// ... 기존 코드 ...` 같은 생략 표기 금지. 검수자가 그대로 덮어씁니다.

   ```
   FILE: _Project/Browser/BrowserDarkModeController.m
   ```
   그 다음 줄부터 ```objc 블록.
3. 응답 맨 앞에 세 가지 요약 — **새로 추가한 파일** / **수정한 기존 파일** / **영향받는 기존 동작**.
4. 응답 맨 뒤에 **기기 테스트 절차**를 번호 목록으로.
5. 내보내기 전 자가 점검 — 헤더에 선언하지 않은 메서드를 외부에서 부르고 있지 않은가 / 블록에서 `self`를 강하게 잡아 순환 참조를 만들지 않았는가 / `NS_ASSUME_NONNULL` 구간의 nullable 표기 / JS 문자열의 따옴표와 이스케이프가 Objective-C 문자열 안에서 올바른가.

## 기기 테스트 절차 (아래를 포함해 보강할 것)

1. 흰 배경 사이트(예: 위키백과)에서 켜기 → 어두워지는가
2. 같은 페이지의 **사진이 색 반전 없이 정상**으로 보이는가
3. 끄기 → 원래대로 돌아오는가
4. 켠 상태로 다른 페이지로 이동 → 새 페이지에도 적용되는가
5. 이미 어두운 사이트(예: 유튜브 다크 테마)에서 켜기 → **밝아지지 않고 그대로**인가
6. 켠 상태로 동영상 재생 → 영상 색이 정상인가
7. 탭을 여러 개 열고 전환 → 각 탭에 적용되는가
8. 스크롤·클릭·새 탭 열기 등 기존 동작이 그대로인가

# v3.4.0 기기 시험 목록

유튜브 재생을 쫓던 코드를 전부 들어내고, 브라우징 본연의 기능과 가독성에 집중한 판입니다.
번호로만 알려주시면 됩니다.

## 1. 네이버 크래시 (이번 판의 핵심)

페이지가 로드될 때마다 **모든 DOM 요소를 순회하며** `getComputedStyle`을 호출하고
인라인 스타일을 쓰던 코드를 제거했습니다. 글자 크기가 100%여도 무조건 실행되던 부분입니다.

- 1-1. `m.naver.com` 로드 → 정상으로 뜨는가
- 1-2. 기사 하나 클릭 → 들어가지는가
- 1-3. 뉴스 기사 안에서 위아래 스크롤 → 끊김 없이 되는가
- 1-4. 탭 3개를 네이버로 열어두고 왔다갔다 → 흰 화면이 뜨는가
- 1-5. ⋯ → `Web Platform Probe` → `1. WebKit Runtime` → **web content deaths 숫자**를 알려주십시오

## 2. 읽기 확대 (새 기능)

TV는 멀리서 보므로 **페이지 전체 확대**가 가장 효과가 큽니다. 글자만이 아니라 레이아웃과
사진까지 같이 커지고, 웹 프로세스에 부하를 주지 않습니다(WebKit이 직접 처리).

- 2-1. `Aa` → `Zoom In` → 페이지 전체가 커지는가 (괄호 안 숫자가 110%로 바뀜)
- 2-2. `Zoom In`을 3~4번 더 → 140~150%에서 소파에서 읽을 만한가
- 2-3. 다른 페이지로 이동 → **확대가 유지되는가**
- 2-4. 앱을 껐다 켜기 → 확대가 기억되는가
- 2-5. `Reset Zoom to 100%` → 원래대로 돌아오는가
- 2-6. 새 탭을 열어도 확대가 적용되는가

## 3. 글자 크기 (동작 방식이 바뀜)

- 3-1. `Aa` → `Increase Text Size` → 글자가 커지는가
- 3-2. 커진 상태에서 페이지 이동 → 유지되는가
- 3-3. `Reset Text Size` → 돌아오는가
- 3-4. 확대(2번)와 글자 크기를 같이 올려도 레이아웃이 깨지지 않는가

> 참고: 예전에는 요소마다 글자 크기를 직접 써넣었고 그래서 무거운 사이트가 죽었습니다.
> 이제는 스타일시트 한 장으로 처리합니다. 사이트에 따라 예전보다 덜 먹히는 곳이 있을 수
> 있는데, 그럴 때는 2번 확대를 쓰시면 됩니다. 그쪽이 TV에서는 더 확실합니다.

## 4. 읽기 모드

- 4-1. 뉴스 기사에서 `Aa` → `Reader Mode` → 본문만 크게 뜨는가
- 4-2. `Reader Text Bigger` / `Smaller` → 바뀌는가
- 4-3. 읽기 모드 끄기 → 원래 페이지로 돌아오는가

## 5. 메뉴에서 사라진 것 확인

아래가 **안 보여야** 정상입니다.

- 5-1. `⚙️` 기어 메뉴에 `Media Experiments` 섹션이 없는가
- 5-2. `⚙️` 기어 메뉴에 `YouTube Capture Hook`이 없는가
- 5-3. `⋯` 메뉴 `Compatibility`에 `1. Inline Video` ~ `4. MediaSource`가 없는가
- 5-4. `⋯` 메뉴 `Web Platform Probe`에 `3. Page Script Errors`가 없는가 (1, 2만 남음)
- 5-5. `⚙️` 기어 메뉴에 `Reading` 섹션(Zoom In/Out/Reset)이 새로 보이는가

## 6. 기본 브라우징 회귀 확인

- 6-1. 주소 입력 → 이동
- 6-2. 뒤로/앞으로
- 6-3. 탭 열기 / 닫기 / 전환
- 6-4. 즐겨찾기 추가 / 해제 / 목록에서 열기
- 6-5. 링크 위에서 클릭 → 새 탭으로 열림
- 6-6. 리모컨 좌/우 → 뒤로/앞으로
- 6-7. 맨 왼쪽 전원 아이콘 → 종료 확인창
- 6-8. 뒤로가기를 끝까지 → 그 탭이 닫히는가
- 6-9. 광고 차단 켜고 뉴스 사이트 → 본문이 멀쩡히 보이는가
- 6-10. 다크 모드 켜기 / 끄기

## 7. 일반 사이트 동영상 (참고)

# 작업 의뢰: tvOS 브라우저 — 시작 페이지

당신은 tvOS 네이티브 앱을 수정하는 Objective-C 개발자입니다. 첨부한 소스 번들이 **현재 저장소의 실제 원본**입니다. 그 내용만을 사실로 삼고, 존재하지 않는 API나 파일을 지어내지 마십시오.

## 공통 제약 — 반드시 지킬 것

1. **Objective-C(ARC)만.** Swift / SwiftUI 금지.
2. **서드파티 라이브러리, CocoaPods, SPM, 외부 CDN·웹폰트 금지.** 시작 페이지 HTML은 네트워크를 전혀 타지 않아야 합니다.
3. **`project.pbxproj`, `Info.plist`, 워크플로 YAML, 스토리보드를 수정하지 마십시오.** 새 소스 파일은 만들어도 되고, 만들었다면 목록을 결과 맨 앞에 적으십시오.
4. **새 프레임워크 링크 금지.** Foundation과 UIKit만 링크되어 있습니다. WebKit은 런타임 접근입니다.
5. **tvOS에 없는 API 금지.** `UIPasteboard`는 tvOS에 없습니다.
6. **기존 동작 회귀 금지.** 커서/스크롤 모드 토글, 터치=현재 탭·클릭=새 탭, Menu=뒤로가기, PlayPause 1회/2회, 탭 오버뷰(최대 5탭), 상단바 포커스, 네이티브 비디오 플레이어, 방향패드·엣지 스크롤과 JS 스크롤 폴백.
7. 새 기능은 `BrowserPreferencesStore`에 설정을 추가하고 고급 메뉴에 토글을 넣으십시오.
8. 코드 스타일은 기존대로.

## 이 작업의 내용

지금 홈 버튼을 누르면 구글(또는 지정한 홈페이지)로 갑니다. 즐겨찾기를 보려면 고급 메뉴를 열어 목록을 뒤져야 합니다. 커서로 바로 고를 수 있는 **타일 격자 시작 페이지**를 만듭니다.

### 요구사항

**1. `BrowserWebView`에 HTML 문자열 로드 추가**

현재 래퍼에는 `loadRequest:`만 있습니다. 다음을 추가하십시오.

```objc
- (void)loadHTMLString:(NSString *)htmlString baseURL:(nullable NSURL *)baseURL;
```

`WKWebView`의 `loadHTMLString:baseURL:`를 기존 런타임 패턴(`NSSelectorFromString` + `respondsToSelector:` + `objc_msgSend`)으로 호출하십시오. `baseURL`은 `nil`로 넘깁니다.

**2. 새 클래스 `BrowserStartPageController`** (`.h`/`.m`)

시작 페이지 HTML 문자열을 만들어 돌려줍니다. 웹뷰에 직접 로드하지 말고 문자열 생성만 담당하게 하십시오.

- 즐겨찾기는 `BrowserFavoritesStore`에서 가져옵니다(작업 10에서 만든 API를 그대로 사용).
- 최근 방문 기록은 `NSUserDefaults`의 `"HISTORY"` 키에서 가져옵니다. 형식은 즐겨찾기와 같은 `@[URL, 제목]` 배열의 배열입니다.

**3. 화면 구성**

- 맨 위에 제목 `tvOS Browser`
- **즐겨찾기 타일 격자** — 최대 12개. 각 타일에 페이지 제목(굵게)과 호스트명(작게)
- 그 아래 **최근 방문** 목록 — 최대 8개, 한 줄씩. 중복 URL은 하나만
- 즐겨찾기가 하나도 없으면 타일 자리에 안내 문구: 고급 메뉴에서 `Add to Favorites`로 추가할 수 있다는 내용

**4. 타일은 평범한 링크로**

타일과 목록 항목은 `<a href="절대URL">`로 만드십시오. 그래야 커서로 클릭했을 때 기존 네비게이션 경로를 그대로 탑니다. **JavaScript로 페이지를 이동시키지 마십시오.** 앱의 링크 처리(현재 탭 / 새 탭 구분)가 동작하지 않게 됩니다.

`:hover`에 테두리와 배경 강조를 넣어 커서가 어디 있는지 보이게 하십시오.

**5. TV용 스타일**

```
배경 #15171a, 글자 #e8e6e3
바깥 여백 60px (TV 안전 영역)
제목 44px 굵게
타일 220×140px, 간격 24px, 모서리 16px, 배경 #22262b
타일 제목 30px, 두 줄까지 말줄임, 호스트 22px 회색
최근 방문 항목 26px, 줄 간격 넉넉하게
```

글꼴은 시스템 기본(`-apple-system`, `sans-serif`)만 쓰십시오.

**6. HTML 이스케이프 — 반드시**

페이지 제목에 `<`, `>`, `&`, `"`, `'`가 들어갈 수 있습니다. 제목과 URL을 HTML에 넣기 전에 모두 이스케이프하십시오. 이것을 빠뜨리면 제목에 따옴표가 있는 즐겨찾기 하나 때문에 시작 페이지 전체가 깨집니다.

**7. 언제 뜨는가**

- `BrowserPreferencesStore`에 `useStartPageAsHome` 추가, 기본값 **YES**.
- 켜져 있으면 `BrowserTabCoordinator`의 `loadHomePage`가 홈페이지 URL 대신 시작 페이지를 렌더하도록 하십시오.
- 끄면 기존 동작(`homePageURLString` 또는 구글)으로 돌아가야 합니다.
- 새 탭을 홈페이지와 함께 여는 경로(`createNewTabLoadingHomePage:YES`)도 같은 `loadHomePage`를 거치므로 자동으로 적용됩니다. 따로 손대지 마십시오.
- 고급 메뉴 `Navigation` 섹션에 토글 추가(`Start Page as Home: On` / `Off`).

**8. 다른 기능과의 관계**

시작 페이지는 앱이 만든 로컬 문서입니다. 강제 다크 모드 주입과 광고 차단 JS 주입이 여기에 동작할 필요가 없습니다. 시작 페이지 문서의 `documentElement`에 `data-browser-start-page="1"` 속성을 넣고, **그 속성이 있으면 두 기능이 주입을 건너뛰도록** 해당 코드에 조건을 추가하십시오.

4. 맨 뒤에 기기 테스트 절차.

## 기기 테스트 절차 (아래를 포함해 보강할 것)

1. 홈 버튼 → 시작 페이지가 뜨는가
2. 즐겨찾기 타일이 저장된 것과 같은 개수·제목으로 나오는가
3. 타일을 커서로 클릭 → 해당 사이트로 이동하는가
4. 타일을 **꾹 눌러 클릭** → 새 탭에서 열리는가 (기존 링크 규칙이 그대로 적용되는지)
5. 최근 방문 목록이 나오고 클릭하면 이동하는가
6. 즐겨찾기를 모두 지운 뒤 → 안내 문구가 나오는가
7. 제목에 따옴표나 `&`가 든 페이지를 즐겨찾기에 넣고 → 시작 페이지가 깨지지 않는가
8. 새 탭 열기(고급 메뉴 `Open New Tab`) → 시작 페이지가 뜨는가
9. 토글을 끄기 → 홈 버튼이 원래 홈페이지로 가는가
10. 강제 다크 모드를 켠 상태에서 시작 페이지 → **색이 반전되지 않는가**
11. 시작 페이지에서 방향패드 스크롤이 동작하는가(항목이 많을 때)
12. 기존 동작(모드 토글, 뒤로가기, 탭 오버뷰) 유지 확인

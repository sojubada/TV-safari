# 작업 의뢰: tvOS 브라우저 — 읽기 모드

당신은 tvOS 네이티브 앱을 수정하는 Objective-C 개발자입니다. 첨부한 소스 번들이 **현재 저장소의 실제 원본**입니다. 그 내용만을 사실로 삼고, 존재하지 않는 API나 파일을 지어내지 마십시오.

## 공통 제약 — 반드시 지킬 것

1. **Objective-C(ARC)만.** Swift / SwiftUI 금지.
2. **서드파티 라이브러리, CocoaPods, SPM 금지.** Readability.js 같은 외부 라이브러리를 가져오지 말고 직접 작성하십시오.
3. **`project.pbxproj`, `Info.plist`, 워크플로 YAML, 스토리보드를 수정하지 마십시오.** 새 소스 파일은 만들어도 되고, 만들었다면 목록을 결과 맨 앞에 적으십시오.
4. **새 프레임워크 링크 금지.** Foundation과 UIKit만 링크되어 있습니다.
5. **tvOS에 없는 API 금지.** `UIPasteboard`는 tvOS에 없습니다.
6. **기존 동작 회귀 금지.** 커서/스크롤 모드 토글, 터치=현재 탭·클릭=새 탭, Menu=뒤로가기, PlayPause 1회/2회, 탭 오버뷰(최대 5탭), 상단바 포커스, 네이티브 비디오 플레이어, 방향패드·엣지 스크롤과 JS 스크롤 폴백.
7. 새 기능은 `BrowserPreferencesStore`에 설정을 추가하고 고급 메뉴에 항목을 넣으십시오.
8. 코드 스타일은 기존대로.
9. **동기 JS 평가는 런루프를 돌립니다.** 반복 타이머나 `CADisplayLink`에서 호출하지 마십시오. 읽기 모드 전환은 사용자가 메뉴를 고를 때 한 번만 일어나므로 문제없습니다.

## 이 작업의 내용

TV는 2~3미터 떨어져서 봅니다. 본문 글씨가 작고 주변 요소가 많으면 읽기 어렵습니다. 본문만 뽑아 큰 글씨로 다시 그리는 기능입니다.

### 요구사항

**1. 새 클래스 `BrowserReaderModeController`** (`.h`/`.m`)

본문 추출 JS 생성, 적용, 해제, 상태 조회를 담당합니다.

**2. 본문 추출 — 직접 구현**

점수 기반으로 본문 후보를 고르십시오.

- 후보 수집: `article`, `main`, `section`, `div`, `td` 중 텍스트가 일정량 이상인 요소.
- 점수 계산:
  - 요소 안의 **순수 텍스트 길이**가 클수록 높은 점수
  - **링크 밀도**(링크 안 텍스트 길이 ÷ 전체 텍스트 길이)가 높을수록 감점. 0.5를 넘으면 후보에서 제외
  - `article`, `main` 태그에 가산점
  - class/id에 `article`, `content`, `post`, `entry`, `body`, `story`가 들어가면 가산점
  - class/id에 `nav`, `menu`, `header`, `footer`, `sidebar`, `comment`, `share`, `related`, `ad`, `banner`, `promo`, `popup`가 들어가면 감점
  - 문단(`p`) 개수에 비례해 가산점
- 최고 점수 요소를 본문으로 삼고, **부모가 비슷한 점수면 부모로 한 단계 올라가** 잘린 본문을 줄이십시오.
- 제목은 `og:title` 메타 → `h1` → `document.title` 순으로 찾습니다.
- 본문에서 `script`, `style`, `noscript`, `form`, `button`, `nav`, `aside`, `footer`, `header`와 광고성 class/id 요소를 제거하십시오. `img`, `figure`, `figcaption`, `blockquote`, `pre`, `code`, `ul`, `ol`, `table`은 남기십시오.

**3. 적용 불가 판정**

추출한 본문의 순수 텍스트가 **400자 미만**이면 읽기 모드를 적용하지 마십시오. 대신 "읽을 만한 본문을 찾지 못했습니다"라는 Alert를 띄우고 원래 페이지를 그대로 두십시오. 억지로 적용해 빈 화면을 보여주는 것이 가장 나쁩니다.

**4. 렌더링 — 원본 보존과 복원**

- 교체 전에 `document.documentElement.innerHTML`을 `window.__browserReaderOriginalHTML`에 보관하십시오.
- `document.documentElement`에 `data-browser-reader-mode="1"` 속성을 설정하십시오. 다른 기능이 읽기 모드 여부를 판별하는 표시입니다.
- 해제: 보관한 HTML로 되돌리고 속성을 제거합니다. **보관본이 없거나 복원이 실패하면 페이지를 다시 로드**하십시오.
- 페이지를 이동하면 읽기 모드는 자동으로 풀립니다(상태는 페이지 단위). 새로 로드된 페이지에 자동으로 다시 적용하지 마십시오.

**5. TV용 스타일**

```
배경 #15171a, 글자 #e8e6e3, 링크 #7fb3ff
본문 글꼴 크기 34px, 줄간격 1.7
최대 너비 1100px, 가운데 정렬, 좌우 바깥 여백 80px, 위아래 여백 60px
제목 48px 굵게, 소제목 38px
이미지 max-width 100%, height auto, 위아래 여백 24px
인용문은 왼쪽 테두리와 들여쓰기로 구분
```

글꼴 크기는 기존 `textFontSize` 설정과 무관하게 위 값을 쓰십시오.

**6. 다크 모드와의 관계**

작업 7에서 들어간 강제 다크 모드는 `data-browser-reader-mode` 속성이 있으면 주입을 건너뜁니다. 읽기 모드는 이미 어두우므로 중복 반전되면 안 됩니다. **그 속성을 반드시 설정하십시오.**

**7. 스크롤**

읽기 모드 문서도 기존 스크롤 경로(방향패드·엣지 오토스크롤·JS 폴백)로 스크롤되어야 합니다. 본문을 `overflow:hidden`인 컨테이너에 넣지 마십시오. 일반 문서 흐름으로 두십시오.

**8. 설정과 메뉴**

- 고급 메뉴 `Appearance` 섹션에 `Reader Mode` 항목 추가. 현재 페이지가 읽기 모드면 제목을 `Exit Reader Mode`로 바꾸십시오.
- 영구 설정은 필요 없습니다. 페이지마다 켜고 끄는 일회성 동작입니다. `BrowserPreferencesStore`에 값을 추가하지 마십시오.

## 기기 테스트 절차 (아래를 포함해 보강할 것)

1. 긴 기사(뉴스·블로그)에서 켜기 → 본문이 큰 글씨로 깔끔하게 나오는가
2. 본문 중간 이미지가 남아 있고 크기가 적당한가
3. 방향패드 아래로 끝까지 스크롤되는가
4. 끄기 → 원래 페이지로 정확히 돌아오는가
5. 읽기 모드에서 링크를 클릭 → 정상 이동하고 읽기 모드가 풀리는가
6. 본문이 거의 없는 페이지(검색 결과, 홈 화면)에서 켜기 → **빈 화면이 아니라 안내 Alert**가 뜨는가
7. 강제 다크 모드를 켠 상태에서 읽기 모드 진입 → **색이 반전되어 하얘지지 않는가**
8. 읽기 모드 상태로 다른 페이지 이동 → 새 페이지는 원래대로 나오는가
9. 탭 전환 후 돌아와도 문제없는가
10. 기존 동작(모드 토글, 새 탭, 뒤로가기) 유지 확인
